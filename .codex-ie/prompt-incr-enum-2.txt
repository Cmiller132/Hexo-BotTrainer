## Design directions (weigh, pick, measure — not a closed list)
1. **Path-local snapshot stack.** df-pn expands a node only while its
   parent chain is on the current descent path. If the snapshot can
   live on an O(depth) descent stack instead of O(nodes) storage, the
   payload collapses by orders of magnitude. Identify every site where
   an expansion consumes a snapshot whose parent is NOT on the current
   stack (lazy-frontier reveals? stage refreshes? TT-restored
   frontiers?) — those fall back to exact batch, which R-IE1 already
   implements and proved sound. Measure the fallback rate before
   rejecting this design.
2. **Compact sidecar encoding.** R-IE1's observed shapes are tiny
   (means: 2.5 live windows, 4.1 distinct cells, 3.8 kernel cells;
   maxima 6/4 vs capacity 8/8). A variable-length arena encoding sized
   to observed shapes instead of fixed capacity.
3. **Selected-edge reconstruction** — rebuild the parent family from
   the stored edge on demand, paying recompute only where consumed.
Hybrids are allowed. Choose by measured peak payload AND wall retention.
