### A.1 Train vs validation CE — and the rising-loss artifact (explicit)

- **Validation CE is NOT on disk.** Every epoch records
  `validation: {"status": "skipped", "reason": "validation disabled"}`
  (`validation_fraction=0.0`). So there is **no fixed-holdout policy/value CE series** for
  this run. Per project convention, learning is judged by the **external SealBot eval**
  (a fixed, independent opponent — effectively the holdout) plus the component trend.
- **Raw train loss is U-shaped and then RISES — a measurement artifact, not regression:**
  total loss falls 7.392 (ep3) → **minimum 5.902 (ep13)** → then **rises** to 6.163 (ep18);
  policy CE 3.225 → 2.316 (ep13) → 2.503; value CE 0.686 → 0.463 (ep13) → 0.550.
  **Meanwhile the SealBot winrate over the same ep13→18 window is 71.9, 70.3, 73.4, 78.1,
  92.2, 79.7%** — i.e., the model keeps *winning more* while the raw loss climbs. This is the
  documented behavior: the loss is computed against each epoch's **own fresh self-play
  targets**, which sharpen and lengthen as play improves (mean game length rises 32→66 over
  the same window), so the CE floor drifts and the number is **not comparable across
  epochs**. **Conclusion: judge by the eval, which says the model is still improving/strong.**

### A.3 Mean game length / distribution

- **Self-play mean length** (raw_samples/games): 76.8 (ep1) → 84.0 (ep3) → **minimum 31.8
  (ep10)** → back up to 49–71 (ep13–18), 69.3 (ep19). **`truncated_games=0` every epoch.**

- **Not derivable from disk without inference** (not run). Shards store value *targets*

## B) Game quality

### B.1 Termination
**Clean.** All 18 recorded eval epochs report `completed: 64` (no aborted/timed-out eval
games); all self-play epochs report `truncated_games: 0`. Sampled eval games are
`status=completed` with finite lengths (33–105 moves), far below `max_actions=1024`.
**No non-termination, cycling-to-cap, or hung games.**

### B.2 Move quality / pathologies (from records + proxies)
- **No truncation/cap-hitting** → no infinite cycling.
- **Openings are semi-diverse, not degenerate:** a common line `(0,0),(0,2),(-2,2),…`
  recurs, but other games open `(0,0),(0,-2),(1,0)…` and `(0,0),(2,2),(2,0)…` — i.e., the
  opening_temperature (0.6) + Dirichlet noise produce variety, not one canonical line.
  (This is the area the earlier opening-collapse / D6-augmentation work targeted; openings
  are no longer a single orientation.)
- **Deeper tactical "blunder" auditing was not performed** (would need engine replay +
  an oracle); the strong winrate vs SealBot best@50ms is the practical quality signal.

### B.3 Policy sharpness / entropy (the "diffuse head" concern)
Measured on current self-play shards (`_diag_exploration.py`, MCTS visit-*target* entropy):
- **ep~19:** opening eff-moves **5.4** (mean entropy 1.69), mid **2.4**, late **2.1**;
  median top-move target prob **0.72**; move dispersion median 6 hex, 43.4% of moves >6 hex
  from the running centroid; mean game length 68.
- **vs earlier (≈ep2, post-fix baseline I measured):** top-move prob was 0.86, mid/late
  eff-moves 1.7–1.8, dispersion 18% >6 hex.
- **Reading:** the policy *target* is **not** getting sharper over training (if anything
  slightly more diffuse), and dispersion is up — but both are **confounded**: (a) games are
  much longer now (68 vs ~46 moves) and spread across more board, inflating dispersion; (b)
  the opening is *intentionally* diffuse by design (widening_max_children=96, hot-opening
  temperature schedule, Dirichlet root noise); (c) late-game balanced positions in
  competitive wins legitimately have several good moves. **Critically, this is the MCTS
  visit-target entropy, not the network's raw policy-head prior** (compact shards drop
  `root_prior_policy`), so it does **not** directly answer "is the policy head sharpening" —
  that needs inference (not run). Given the 80–92% winrate, the diffuse *target* is clearly
  not preventing strong play, but **policy-head sharpness remains an unmeasured open
  question** (see red flags).

## Bottom line

- **Learning is healthy and the model genuinely, reliably beats SealBot best@50ms** — 0% →
  92% winrate, ≥65% sustained since epoch 11, ~80% currently. This is the trustworthy
  signal; the **rising raw train loss after ep13 is the known moving-target artifact**, not
  a regression (confirmed by the simultaneously-rising winrate).
- **Game quality is sound:** clean termination (0 truncations, all eval games completed),
  finite competitive game lengths, semi-diverse openings, no cycling/cap pathologies.

### Red flags / things to watch
1. **No internal validation holdout** (`validation_fraction=0`). The run leans entirely on
   the 64-game SealBot eval. A small fixed-holdout set (or a checkpoint loss-decomposition
   on a frozen sample) would de-risk the artifact ambiguity — not currently on disk.
2. **Policy-head sharpness and value calibration are unmeasured** here (shards drop the raw
   prior; no predicted-vs-actual on disk). The MCTS-target entropy is *not* sharpening, but
   that's confounded. Worth a one-off offline inference pass on a frozen checkpoint when the
   GPU is free.
3. **ep17→ep18 winrate dip (92%→80%)** — almost certainly 64-game noise, but watch whether
   ep19–20 stay in the high-70s+/recover.
4. **Move dispersion rose to ~43% >6-hex** at ep19. Likely longer competitive games +
   intentional opening exploration, not pointless scatter (the model is winning), but it's
   the same metric that flagged the earlier "middle-of-nowhere" issue — worth confirming it
   tracks game length rather than degrading.
5. **Recurring RAM-watchdog warns** (free RAM dipped to 0.7–3.9 GB at training-pass peaks,
   per `supervisor_wsl.log`) — operational, not a learning issue, but a stability watch.
