## 3. THE PROPOSITION: decisiveness via an Lc0-style moves-left utility

**Problem it fixes (measured):** a calibrated value head is *structurally indifferent* among equally-winning moves (binned head: 65 bins ≈ 0.031 resolution; measured flat-tops: top-12 candidates within 0.025 at the 64 engine-verified squander positions). Won games drift, drift grows blobs past the crop, the rest follows. The played squander moves were never value-endorsed (value-argmax only 25%) — the failure is direction-less choice, not bad preferences.

**Engine genealogy (the owner asked "how do KataGo/Lc0 do this"):**
- **KataGo** has NO moves-left head. It solves slack play with **score utility**: an auxiliary head predicts final score margin; search maximizes win-utility + bounded f(expected margin). Works because Go has a natural margin currency. Crucially it runs **during selfplay**, so utility-shaped visits become policy targets and the net *internalizes* decisive play.
- **Lc0** (chess: binary outcome, no margin) invented the **moves-left head utility**: small, bounded, |Q|-gated selection-time bonus preferring quicker wins / longer losses.
- **Hexo is chess-like** (first 6-in-row ends it; no margin) → the Lc0 mechanism is the correct port; adopt KataGo's selfplay-distillation lesson (utility on in selfplay+eval symmetrically) once the steering head is sound.

**The design (full spec `scripts/_wf_s3_RESULT_design.json`; summary `docs/analysis/STAGE3_MOVES_LEFT_FEASIBILITY.md`):**
`U_ml(e) = − w_ml · g(Q_e) · tanh((M_e − M_n)/m_scale)`, added ONLY in PUCT edge scoring (`mcts_tree.rs:609`), never in value backprop (value purity; no virtual-loss interaction; ml accumulates in separate (ml_sum, ml_weight) on REAL backups only). `g` gates on search-averaged |Q| > 0.6, win-side-only by default. Defaults w=0.03 (hard tanh cap), m_scale=32, median-of-bins decode. Delta-vs-sibling form cancels the head's absolute bias. Terminal leaves contribute exact path distance (use `path_len − i − 1`; the −1 was a verifier correction). Five build layers (Python head export with `forward_policy_value` untouched → Rust wire parse fail-loud-when-enabled → tree stats + bonus → config knobs `[selfplay.moves_left_utility]` → fp16/TRT phase-1 refuse-adoption), ~3–5 days, every layer defaults-off with a byte-equivalence off-switch test. **Never rebuild the Rust extension while the run is live.**

**Evidence it works and is safe (one-ply probe, adversarially re-derived):** at k∈[0.2,0.5] it flips 12.5–29.7% of the 64 real squander-point choices toward predicted-faster conversion (100% of flips reduce predicted moves-left; median value cost 0.0009), with **0/15 endgame-control and 0/24 midgame flips** (controls only touched at k=1.0: 2/24). The formula's slope sits inside that validated envelope at |Q|∈[0.8,1.0].

**Why NOT enable today:** the current moves_left head is flood-damaged — wrong-sign sibling gradients (−3.7/−19.1 at true-ml 30/60: it ranks slower moves as faster) and chance-level within-game ordering. It would steer search backward. It is healing with the cleaned window (training loss 3.65 → 3.36 by ep13).

**L0 enablement gate (run per new checkpoint, CPU ~hours, scripts `_wf_s3_mlaudit.py` + the sibling probe — check `scripts/` then `scripts/archive/`):** conversion-zone (<60 true-ml) within-game Spearman ≥ 0.6 AND [0,5) median-decode MAE ≤ 15 AND end-vs-mid pairwise ≥ 0.85 AND correct-sign sibling decrements at ml=10/30/60. Healthy reference heads pass (0.62/9.9–13.3/0.87–0.91/correct); ckpt12 fails everything. If healing stalls ~3 more epochs: raise `moves_left_weight` 0.1→0.3–0.5 (one-line, next bounce). The suspected plies-vs-decisions unit mismatch was **refuted by measurement** — units are consistent end-to-end; no retraining needed for units.

**Known design risks (verified as disclosed):** sign-rudder — the raw one-ply |v|>0.6 read predicted the true winner only 48% at squander points (mitigations: gate on search-averaged Q, win-side-only, 0.03 cap); policy targets intentionally absorb utility-shifted visits (KataGo-lesson feature IF the head is sound — monitor policy CE in the A/B); stacking with C1/C3 confounds attribution (hold them fixed in the A/B; if the utility works, RELAX C1 rather than stack); one-ply-probe→full-search transfer gap (covered by ladder step 5: re-run the 103-position probe through the real Rust search); cross-move ml discontinuity (+25 jump across turn-passing moves — add parity-mixed-sibling telemetry, suppress bonus at mixed nodes).
